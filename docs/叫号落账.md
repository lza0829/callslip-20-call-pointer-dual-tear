# 叫号落账架构（选定：臂A · 同笔多写）

## 选型（全局只此一种，禁止混用）

点叫下一号落账时，号牌状态、窗口当前号指针、叫号事件、等候位次出队在
**同一事务**内同成败；任一侧失败或人为打断，整笔回滚到叫号前快照。

不采用臂B「先钉指针后补状态」：本系统单库单事务即可同笔落账，
无需短窗滞后、补齐任务与读路径滞后标记。臂B 的一切形态
（先钉后补、状态短窗滞后、总览剔除未补齐项）全局不得出现。

## 正确性口径：叫号落账状态与占窗，同听一次提交

落账次序（`app/services/tickets.py::call_next`，同一事务内）：

1. **只读校验**：日闸未封口、窗口开放且空闲、种类可办；
2. **原子认领**：`UPDATE tickets ... WHERE id=? AND status='等候'`
   （重叫卡 `'过号'`）——并发双叫同一号，后到者命中 0 行 → 409，整笔回滚；
3. **条件钉针**：`UPDATE windows ... WHERE id=? AND current_ticket_id IS NULL`
   ——同窗并发双击，后到者 → 409，本笔认领随事务回滚；
4. **叫号事件**：与状态、指针同笔写入，`note` 记状态迁移
   （`等候→办理中` / `过号→办理中`），供读路径按落账次序重放；
5. **提交瞬间同刷**：叫号回执、窗口当前号列、号牌状态列、等候墙（出队+在办）、
   叫号流水、窗口页在办条、总览办理中桶。

细则：

- **位次出队的物化 = 状态迁出 `等候`**：等候墙按状态过滤，认领提交即出队，
  不另留队列残影；等候墙不得因本次叫号新增可解释漂移。
- **并发连接**靠 `busy_timeout` 等待先胜者提交，再由条件守卫干净判负
  （400/409），不得 500 假绿，不得一成一半。
- **重放**：各读路径（等候墙/窗口列/总览/流水）均为已提交状态的纯查询，
  等价于按落账次序重放到当前提交点；钉针集合必等于办理中集合。
- **叫号探针**（`app/services/probe.py::alignment_probe`，`GET /api/叫号探针`）：
  假钉窗收口的唯一全局口径。按落账次序重放窗指针事件，与窗口当前号、
  号牌状态列、等候墙、总览桶、种类序号页逐一对照；半截（状态办中当前号空、
  当前号钉状态未办中、审计叫号无落账）与双落（同号连叫）都必须对出
  对齐缺口。探针报「对齐」是叫号成功灯成立的唯一判据。

## 同刷约定

`POST /api/叫号` 与 `POST /api/号牌/{id}/重叫` 返回**同刷包**：
回执 + 窗口列 + 等候墙 + 叫号流水 + 总览，取自同一事务快照。
叫号入口据包整体刷新，**禁止只刷叫号回执**。

## 验证

`backend/tests/test_call_commit.py`：同刷一致性、多写中段失败回滚、
人为打断回滚、并发双叫同一号、同窗双击、全流程重放不变量、重叫守卫。

`backend/tests/test_alignment_probe.py`：四类假钉窗夹具（状态办中当前号空、
当前号钉状态仍等候、审计成功办理页无号、同号连点半截双落）的探针对照、
连点收敛、全流程探针对齐、叫号 API 与各读接口同刷。

运行：`pip install -r backend/requirements-dev.txt && cd backend && python -m pytest tests/`。

## 范围外（另立需求）

- 独占并叫：多窗抢号的排队/锁策略。本架构只保证败者干净回滚，不定义谁该赢。
- 过号命运：过号保留时长、自动重叫、回收规则。
